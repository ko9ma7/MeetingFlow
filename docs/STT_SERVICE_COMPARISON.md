# STT 관련 서비스 검토와 MeetingFlow 적용 판단

검토 기준은 한국어 회의를 노트북에서 장시간 녹음하면서 앞부분부터 확인·수정할 수 있는지, 무음과 잡음에 견디는지, 최종 정확도를 다시 높일 수 있는지, 배포 라이선스가 적합한지다.

| 프로젝트 | 실제 용도 | 장점 | MeetingFlow 판단 |
|---|---|---|---|
| [RealtimeSTT](https://github.com/KoljaB/RealtimeSTT) | Whisper 계열 실시간 마이크 STT 오케스트레이션 | Silero/WebRTC VAD, 사전 녹음 버퍼, 실시간 임시 문장과 안정화 문장 콜백, 외부 오디오 공급과 지연 큐 제한 | 설계 패턴을 채택한다. 현재 3초 조각 미리보기, 백로그 제한, 임시/확정 원문 분리를 유지하고 VAD 기반 발화 경계는 다음 엔진 개선 후보로 둔다. |
| [Moonshine](https://github.com/moonshine-ai/moonshine) | 캐시 기반 진짜 스트리밍 STT | 입력과 디코더 상태를 재사용해 반복 전체 디코딩을 피함, 줄 업데이트 이벤트, VAD, 반복 토큰 제한, 스트리밍 화자 갱신 | 기술적으로 가장 유망한 선택 엔진이다. 다만 한국어 모델은 Moonshine Community License의 비상업 조건이 있어 기본 배포에 포함하지 않고, 사용자가 라이선스를 확인한 뒤 켜는 실험 엔진으로만 검토한다. |
| [CrisperWhisper](https://github.com/nyrahealth/CrisperWhisper) | Whisper 결과의 축약을 줄이고 단어 타임스탬프를 정밀화하는 후처리/정밀 전사 | 축어 전사와 긴 음성 정밀화에 유리 | 실시간 첫 화면용이 아니다. 저장된 WAV에 대한 선택적 정밀 재전사 단계로 유지한다. CPU 노트북에서는 처리 시간이 음성 길이보다 길 수 있다. |
| [capcut-tts-api](https://github.com/K07VN/capcut-tts-api) | 텍스트를 음성으로 만드는 TTS API | 다양한 음성 합성 | STT가 아니므로 회의 기록 엔진으로 넣지 않는다. 나중에 AI 요약 읽어주기 기능에만 별도로 검토할 수 있다. |
| [STTextView-Plugin-Neon](https://github.com/krzyzanowskim/STTextView-Plugin-Neon) | Apple STTextView용 구문 강조 플러그인 | Tree-sitter/Neon 기반 편집기 강조 | 음성 인식이 아니며 WPF에도 직접 적용되지 않는다. |

## MeetingFlow의 권장 처리 방식

1. 녹음 중에는 3초 조각을 순차 전사해 즉시 보여주고 사용자가 편집할 수 있게 한다. 이 내용은 임시 초안이며 자동 저장한다.
2. 원본 WAV는 항상 진실의 원본으로 먼저 저장한다. 화면 미리보기가 실패하거나 앱이 종료돼도 같은 회의 기록에서 재전사한다.
3. 무음은 녹음 파일에서 강제로 삭제하지 않는다. VAD는 전사할 구간과 문장 경계를 정하는 데 사용해 CPU 낭비와 환각을 줄인다. 앞말 잘림 방지를 위해 발화 전 버퍼를 둔다.
4. 정지 뒤에는 faster-whisper가 전체 WAV를 다시 정밀 전사해 초안을 갱신한다. 반복 문구, 비정상 속도, 긴 무음 구간은 환각 방지 필터로 거른다.
5. 화자 A/B/C/D는 전사와 별도 메타데이터로 관리한다. 사용자가 이름을 바꾸면 오디오를 다시 처리하지 않고 모든 원문과 보고서 표기만 갱신한다.
6. AI 보고서는 검토·확정한 STT 원문에서만 만든다. OpenAI, Gemini, Anthropic, 호환 API는 공급자 어댑터로 선택하고 API 키는 Windows 사용자 암호화 저장소에 보관한다.

## 속도와 정확도의 현실적인 기준

- “실시간”은 음성이 끝나기 전에 임시 문장이 갱신된다는 뜻이지, 최종 정밀 전사가 항상 1배속보다 빠르다는 뜻은 아니다.
- CPU 전용 노트북에서는 `small` 또는 `medium` 정밀 모델보다 작은 실시간 모델을 쓰고, 정지 뒤에 더 큰 모델로 다시 처리하는 2단계 방식이 안정적이다.
- 긴 회의는 한 번에 결과를 기다리지 않는다. 조각별 초안, 구간별 체크포인트, 저장된 WAV 재시작을 기본으로 삼아야 한다.
- 화자 분리는 추가 연산이 크고 실시간 중 화자 번호가 뒤늦게 바뀔 수 있다. 실시간에는 A/B/C 초안을 표시하고 정지 뒤 전체 오디오로 확정하는 방식이 적합하다.
